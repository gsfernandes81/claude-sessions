  `src/menu.rs` (state, pure), draws with `src/render.rs` (to the approved screens, tested
  against the mockup files themselves at 40×24 and 80×24), reads keys through `src/term.rs`
  (raw mode, click-only mouse, restore on panic) and acts through `src/launch.rs` (attach,
  resume, new, shell, close, offload-to-make-room). `src/ui.rs` is the contract between them.
- **Tests: 363, green** on x86_64 here (the zmx switch; CI also runs them against the real zmx), including `tests/menu_pty.rs` — an idle
  menu emits zero bytes on a real pty, calibrated by a registry change that does redraw it.
- **It was driven by hand through `pyte`** on a pty with stand-in `abduco` and `claude`: the
  list, cursor by arrows and clicks, the keys screen, the close dialog, attach and detach
  (mockup 6's status line), a failed resume (mockup 5, from real stderr), `n`, `s`, resizing
  from 80 down to the refusal at 6 columns. The driver script is not in the repo; rebuild it
  from `tests/menu_pty.rs` and `src/launch.rs`'s stand-ins if needed — pyte installs with pip.
- **Time to first frame: ~1.3 ms** for six slots (target: under 100 ms on the ssh path).

   both kernel-only and both reported, not acted on (design § Activity, measured): every TCP
   socket's bytes from the kernel's socket-diagnostics netlink, added to the slot's window —
   checked readable without privilege in the cloud dev container — and a freeze of **claude
   alone**, carried from pass to pass, thawed when anything claude did not start starts, any
   member but claude exits, the others move past the budget, or on attach. The third blind
   spot, a timer of claude's own, has **no kernel answer** that works well (owner agreed,
   2026-10-07): the hook-read hold stays. **Next is unchanged:** read the logs. What is new
   in them:
   - `(tcp …)` beside the bytes. `(tcp ?: the dump was refused)` means the fleet's kernel
     refused the dump — it is pass-wide, on every slot measured in that pass, never one
     slot's; the pass also prints `tcp sockets could not be read`. `(tcp ?: a member's
     descriptors could not be listed)` on a slot is a member whose counters read and
     `/proc/<pid>/fd` did not, which no ordinary program produces; a setuid member reads
     instead as `N of its processes could not be read … unknown`, every pass it lives.
     Floors learned before the upgrade are `read`/`write` alone and age out over a day, so the
     first day holds slots to a lower line than later days — erring active.
   - The thing to count: lines ending `claude itself started … / moved …, which the freeze
     would have stopped` — what a freeze would break — and on each, whether tcp bytes moved
     (a turn or a tool, when of a turn's size) or none (housekeeping, or a turn whose socket
     closed inside the window — the count has slack both ways, design § Activity, measured).
     **But the count comes only from slots the offloader keeps** — a timer pending,
     background work, waiting for you — because the offloader kills an ordinary idle slot at
     or before the pass where the rule would first freeze it. Read each line beside the
     slot's `kept — …` line later in the same pass's output — the measured lines come first,
     then the offloader's — and expect timer slots to be most of the count. Whether a freeze
     would break an ordinary idle slot, these logs cannot say while the kill runs; holding
     it off is the owner's call.

## Open, not urgent

- **A `/loop` turn that ends in an API error is not held for its keepalive** (review of
  0.4.7): it fires `StopFailure`, which `hooks_config` does not install, and Claude Code arms
  the keepalive after it. Not a regression (0.4.6 let go at the same moment). The shape: add
  `StopFailure` to the async events, apply it as a `Stop` without a list, and arm the same
  keepalive hold when a non-durable one-shot on record has come due. `StopFailure` lists no
  crons, so it must also hold a wake-up whose own hook a newer timer write refused, which
  until then is recorded only by that turn's `Stop`. It changes `hooks-config`, so it is its
  own release.

- **The Archived heading is modelled as a row** (`RowKey::ArchiveFold`), carrying its count in
  `age` and `closed: true` only so the header does not count it; every consumer special-cases
  it. Raised by the v0.3.5 review and left: a proper split between selectable lines and
  sessions is a larger rework than the feature needed.
- **Archive marks are never cleaned up** when their transcript goes, and every poll re-reads
  them. Minor beside the transcript reads the poll already does.

- **A long-interval wake tool**, deferred and possibly unnecessary. `ScheduleWakeup` clamps at
  an hour, and since a pending timer pins a slot, a loop waiting longer holds its memory the
  whole time. Worth building only if long waits turn out to be common, and it needs a resumed
  session to accept a replayed prompt, which nobody has tested.
- **Where this repo is checked out inside a dev container**: `~/.local/share/src/claude-sessions`,
  chosen by an agent on the owner's "anywhere of your choice". `~/.local/share` is the one
  persisted volume; `~/.local/share/claude-sessions` is **the registry** and must not also be
  a source tree. A second bind mount in that container's compose file is the cleaner answer,
  and the owner's to add.

## Things worth knowing before you trust something

- **A claude.ai cloud container is x86_64 and has `cc`**, unlike the dev container. The pinned
  aarch64 target builds there but its tests cannot run: `rustup target add
  x86_64-unknown-linux-musl` and pass `--target x86_64-unknown-linux-musl` to clippy and test,
  as CI does.
- **A cloud container runs the tests as root; CI does not.** A test that writes somewhere only
  root may (`/`, a record's `cwd`) passes here and fails on the runner — it cost the first
  v0.3.3 push. Before pushing a test that touches the filesystem, run the unit binary
  unprivileged: copy `target/x86_64-unknown-linux-musl/debug/deps/claude_sessions-<hash>` to
  `/tmp` and run it with `runuser -u nobody --` from `/tmp`.
- **Cloud sessions cannot push tags** (the git proxy answers 403), which is why CI cuts
  releases on a version bump.
- **Commit with explicit paths.** `git add -A` once swept the agents' worktrees in as embedded
  repositories; `.claude/worktrees/` is ignored now, but read `git diff --cached --stat`.
- **Test the session holder for real, not only with a stand-in.** v0.3.8 passed every test and
  turned swipes into arrow keys on the first box, because only the real abduco switched to the
  alternate screen. `tests/zmx_real.rs` exists for that; extend it, not the stand-ins, for
  anything about what reaches the terminal.
- **`pkill -f`/`kill $(pgrep -f …)` matches the shell running it** — it killed this session's
  own shell once (exit 144). Select by `/proc/<pid>/comm` and skip `$$`.
- **`/proc/meminfo` in a container describes the host.** The ceiling is the cgroup.
- **`$CLAUDE_CONFIG_DIR/sessions/<pid>.json` accumulates dead files**; `procStart` separates
  live from stale.
- **A git push from inside `infra-dev` needs an askpass helper**: the global `insteadOf`
  rewrite sends `https://github.com/` to SSH. What works: a remote of
  `https://github.com:443/...` plus `GIT_ASKPASS` pointing at a script that echoes
  `gh auth token`.

# Handoff — the menu, and the measured offloader

## First orders

**Read this, then [`../../CLAUDE.md`](../../CLAUDE.md), then [`../design.md`](../design.md).**
Released through `v0.4.6`, which `infra` pins. `main` carries the measured offloader and
`claude-sessions keepalive` (item 1), reviewed and **not released**. The next step is the
owner's: a version bump releases it (CLAUDE.md § Release), then item 1's infra handoff. Do
not deploy, start, stop or offload anything yourself.

## State of `main`

- **The menu works** — `claude-sessions` at a terminal. `src/run.rs` (the loop) drives
  `src/menu.rs` (state, pure), draws with `src/render.rs` (to the approved screens, tested
  against the mockup files themselves at 40×24 and 80×24), reads keys through `src/term.rs`
  (raw mode, click-only mouse, restore on panic) and acts through `src/launch.rs` (attach,
  resume, new, shell, close, offload-to-make-room). `src/ui.rs` is the contract between them.
- **Tests are green** on x86_64 here; CI also runs them against the real zmx. They include
  `tests/menu_pty.rs` — an idle menu emits zero bytes on a real pty, calibrated by a registry
  change that does redraw it.
- **Time to first frame: ~1.3 ms** for six slots (target: under 100 ms on the ssh path).

## What is next

1. **The offloader acts on measured activity alone, and claude can ask for time** (owner,
   2026-10-08): no rule reads Claude Code for the offload decision any more (the
   `session_crons` work it replaces is kept, unmerged, on `session-crons-0.4.7-wip`). A slot is offloaded when it is detached, not kept alive, and
   measured quiet — no window over its byte budget or 50 ms/s of CPU — for 10 minutes (design
   § The offloader, § Activity, measured). Gone: the timer records, the `background` list,
   the idle-since-`Stop` clock, the waiting-for-you and process-under-claude holds, the
   transcript-write clock, and the freeze shadow. The hooks now feed the menu only, and
   `PostToolUse`, `SubagentStart` and `SubagentStop` are no longer installed. Work that waits
   quietly is held by `claude-sessions keepalive <duration>` (mandatory, at most 12h, `0` ends
   it), and the keep-alive skill tells claude when and for how short a time.
   A keep-alive belongs to the process that asked for it, and a pass decides only on the
   readings it took itself, of the slot's current claude.
   **For infra**, at the pin bump that takes it, from whatever is pinned now:
   - the build regenerates the hooks drop-in: five events, every one but `SessionStart` and
     `SessionEnd` async with no timeout; `dev/README.md`'s hooks rows say so and the rows for
     the removed hooks go;
   - `hook.log` counts as expected a `SessionEnd` dropped behind an async hook stalled on the
     box's load; any other drop means a lock wait (15 s, or 2 s for a `SessionStart` that
     cannot bind) ran out;
   - the skill is installed at every container start, into the config directory's volume
     (design § Where the hooks live has the two lines);
   - the offload timer stays at a few minutes: 10 or more never offloads (design § How
     `claude-sessions offload` reads those rules);
   - the binary checks on `background_tasks` and the timer tools go, and the pass log kept for
     the freeze decision is no longer needed for one.

## For the owner to look at — flagged, not changed

- **New wording** the mockups did not draw (design § How the menu acts): closing an offloaded
  slot, and no room with nothing offloadable.
- **Mockup 4 now offers an idle session** ("retire the old tunnel", idle 14m). The approved
  screen offered "mount guards on one", which was already offloaded — impossible to offload
  again, and in the grouped list it would sit visibly under Offloaded.
- **A pending timer no longer shows on the list, and no longer keeps a slot.** A slot waiting
  on a timer is at its prompt, so it is under Idle; claude holds it with `keepalive`.
- **`CLAUDE.md`'s "nothing is colour-only" rule was reworded** for the owner's choice of bold
  and dim over glyph marks: state is in words, by the heading; unread and attached are
  emphasis on top.
- **Closed is read from Claude Code's own store** (owner, 2026-10-03, workspace only): every
  conversation started in the workspace that is not running, whoever started it, resumed in a
  slot on `Enter`. This replaced the registry's closed slots as the source, which also answers
  infra#3's point that a slot's earlier conversations dropped off the list.
- **Untested: whether `claude --resume` opens a `/clear`-only transcript.** It no longer
  matters to the code — such a transcript counts as no conversation either way — but it could
  not be settled here: interactive `claude` in a cloud container stops at onboarding, and a
  login is not ours to do. Infra's bring-up checks it.
- **A record older than 0.3.3 has no `transcript_path`**, so its conversation is looked for
  under `CLAUDE_CONFIG_DIR`. If the offload timer ran with a different one than claude, an idle
  old slot would read as never prompted and be closed rather than offloaded — nothing deleted,
  but its row would leave the menu. Every hook event records the path, so this only touches
  slots idle since before the upgrade. Infra confirmed on infra#3 that the loop and every
  slot share one `CLAUDE_CONFIG_DIR` (the base image's `ENV`).
- **Ages read up to a minute low** — the price of every age ticking together once a minute
  (design § The menu).

## Open, not urgent

- **The Archived heading is modelled as a row** (`RowKey::ArchiveFold`), carrying its count in
  `age` and `closed: true` only so the header does not count it; every consumer special-cases
  it. Raised by the v0.3.5 review and left: a proper split between selectable lines and
  sessions is a larger rework than the feature needed.
- **Archive marks are never cleaned up** when their transcript goes, and every poll re-reads
  them. Minor beside the transcript reads the poll already does.

- **Where this repo is checked out inside a dev container**: `~/.local/share/src/claude-sessions`,
  chosen by an agent on the owner's "anywhere of your choice". `~/.local/share` is the one
  persisted volume; `~/.local/share/claude-sessions` is **the registry** and must not also be
  a source tree. A second bind mount in that container's compose file is the cleaner answer,
  and the owner's to add.

## Things worth knowing before you trust something

- **A claude.ai cloud container is x86_64 and has `cc`**, unlike the dev container. The pinned
  aarch64 target builds there but its tests cannot run: `rustup target add
  x86_64-unknown-linux-musl` and pass `--target x86_64-unknown-linux-musl` to clippy and test,
  as CI does.
- **A cloud container runs the tests as root; CI does not.** A test that writes somewhere only
  root may (`/`, a record's `cwd`) passes here and fails on the runner — it cost the first
  v0.3.3 push. Before pushing a test that touches the filesystem, run the unit binary
  unprivileged: copy `target/x86_64-unknown-linux-musl/debug/deps/claude_sessions-<hash>` to
  `/tmp` and run it with `runuser -u nobody --` from `/tmp`.
- **Cloud sessions cannot push tags** (the git proxy answers 403), which is why CI cuts
  releases on a version bump.
- **Commit with explicit paths.** `git add -A` once swept the agents' worktrees in as embedded
  repositories; `.claude/worktrees/` is ignored now, but read `git diff --cached --stat`.
- **Test the session holder for real, not only with a stand-in.** v0.3.8 passed every test and
  turned swipes into arrow keys on the first box, because only the real abduco switched to the
  alternate screen. `tests/zmx_real.rs` exists for that; extend it, not the stand-ins, for
  anything about what reaches the terminal.
- **`pkill -f`/`kill $(pgrep -f …)` matches the shell running it** — it killed this session's
  own shell once (exit 144). Select by `/proc/<pid>/comm` and skip `$$`.
- **`/proc/meminfo` in a container describes the host.** The ceiling is the cgroup.
- **`$CLAUDE_CONFIG_DIR/sessions/<pid>.json` accumulates dead files**; `procStart` separates
  live from stale.
- **A git push from inside `infra-dev` needs an askpass helper**: the global `insteadOf`
  rewrite sends `https://github.com/` to SSH. What works: a remote of
  `https://github.com:443/...` plus `GIT_ASKPASS` pointing at a script that echoes
  `gh auth token`.

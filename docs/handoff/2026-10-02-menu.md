## State of `main`

- **The menu works** — `claude-sessions` at a terminal. `src/run.rs` (the loop) drives
  `src/menu.rs` (state, pure), draws with `src/render.rs` (to the approved screens, tested
  against the mockup files themselves at 40×24 and 80×24), reads keys through `src/term.rs`
  (raw mode, click-only mouse, restore on panic) and acts through `src/launch.rs` (attach,
  resume, new, shell, close, offload-to-make-room). `src/ui.rs` is the contract between them.
- **Tests: 168, green** on x86_64 here and in CI, including `tests/menu_pty.rs` — an idle
  menu emits zero bytes on a real pty, calibrated by a registry change that does redraw it.
- **It was driven by hand through `pyte`** on a pty with stand-in `abduco` and `claude`: the
  list, cursor by arrows and clicks, the keys screen, the close dialog, attach and detach
  (mockup 6's status line), a failed resume (mockup 5, from real stderr), `n`, `s`, resizing
  from 80 down to the refusal at 6 columns. The driver script is not in the repo; rebuild it
  from `tests/menu_pty.rs` and `src/launch.rs`'s stand-ins if needed — pyte installs with pip.
- **Time to first frame: ~1.3 ms** for six slots (target: under 100 ms on the ssh path).

3. **Things only a real box can answer** — collect them into the owner's bring-up notes, do
   not guess:
   - The managed-settings drop-in raises **no approval dialog** on first start (docs say so;
     unconfirmed).
   - A slot started by the menu **binds**: `doctor` shows its pid and events. This rests on
     claude's process name being `claude` and on the `exec` in the start line.
   - claude's **stderr is captured to a file for the whole session**. If Claude Code ever
     writes something interactive to stderr, it would vanish; look on the first real start.
   - `offload --dry-run` output for a few days, before it goes live.
4. **The orphan sweep** logs only. A reminder fires for the owner on 2026-10-08; arming it is

## For the owner to look at — flagged, not changed

- **New wording** the mockups did not draw (design § How the menu acts): closing an offloaded
  slot, and no room with nothing offloadable.
- **Four marks do not fit three columns.** A row that is `!*t@` at once keeps `!*t` and drops
  `@`; widening the marks field would break the approved layout.
- **`docs/mockups.md` says "in a full list of six slots there are two amber characters"**, but
  mockup 1 is six slots with one `!`. The renderer follows the screen; the sentence may be a
  slip.
- **Ages read up to a minute low** — the price of every age ticking together once a minute
  (design § The menu).

## Open, not urgent

- **A long-interval wake tool**, deferred and possibly unnecessary. `ScheduleWakeup` clamps at
  an hour, and since a pending timer pins a slot, a loop waiting longer holds its memory the
  whole time. Worth building only if long waits turn out to be common, and it needs a resumed
  session to accept a replayed prompt, which nobody has tested.
- **Where this repo is checked out inside a dev container**: `~/.local/share/src/claude-sessions`,
  chosen by an agent on the owner's "anywhere of your choice". `~/.local/share` is the one
  persisted volume; `~/.local/share/claude-sessions` is **the registry** and must not also be
  a source tree. A second bind mount in that container's compose file is the cleaner answer,
  and the owner's to add.

## Things worth knowing before you trust something

- **A claude.ai cloud container is x86_64 and has `cc`**, unlike the dev container. The pinned
  aarch64 target builds there but its tests cannot run: `rustup target add
  x86_64-unknown-linux-musl` and pass `--target x86_64-unknown-linux-musl` to clippy and test,
  as CI does.
- **Cloud sessions cannot push tags** (the git proxy answers 403), which is why CI cuts
  releases on a version bump.
- **Commit with explicit paths.** `git add -A` once swept the agents' worktrees in as embedded
  repositories; `.claude/worktrees/` is ignored now, but read `git diff --cached --stat`.
- **A killed abduco server leaves its socket with the attached bit still set.** The mode only
  answers *attached?* for a session already known alive by its pid.
- **`/proc/meminfo` in a container describes the host.** The ceiling is the cgroup.
- **`$CLAUDE_CONFIG_DIR/sessions/<pid>.json` accumulates dead files**; `procStart` separates
  live from stale.
- **A git push from inside `infra-dev` needs an askpass helper**: the global `insteadOf`
  rewrite sends `https://github.com/` to SSH. What works: a remote of
  `https://github.com:443/...` plus `GIT_ASKPASS` pointing at a script that echoes
  `gh auth token`.

# Handoff — the hub

## First orders

**Read this, then [`../../CLAUDE.md`](../../CLAUDE.md), then [`../design.md`](../design.md) §
*The hub*.** The hub is built and tested here, on branch `ccr-87300a0c-3kalf9`, at `0.5.0`;
nothing of it is released or on the fleet. Merging it to `main` **is the release** (the version
bump publishes), and the owner decides when. Do not deploy, start, stop or offload anything.

## What changed

- `claude-sessions` at a terminal is the **hub's menu** over every container named in
  `CLAUDE_SESSIONS_HOSTS` or `~/.config/claude-sessions/hosts`, else `local` — which is the
  old single-container menu, unchanged screen for screen. Mockups 12 to 15 are the home, one
  container focused, a container not answering, and the home's keys; the owner left the
  interface to this repo ("interface is your call", 2026-10-26) and asked for nesting.
- `claude-sessions agent` is each container's half, over `ssh -T`; `agent exec` runs a child
  an action needs at the hub's terminal, over `ssh -t`. Everything that reads or changes a
  container's sessions still runs in the container, from the same code.
- `claude-sessions offload-all` runs every container's pass at once; `offload` honours
  `CLAUDE_SESSIONS_OFFLOAD=0`.
- `claude-sessions install DIR` writes the binary, the hooks drop-in naming `DIR/bin/…` and
  the skill — what the hub's start puts into the volume every container mounts.

## For infra, at the bump that takes 0.5.0

infra's branch of the same name carries the other half (one compose file, the hub image,
the base changes) with the hub's `CLAUDE_SESSIONS_SHA256_*` left as placeholders: they exist
only once CI has built the release. Fill them from the release's `.sha256` assets.

## Not verified here

- **Real ssh and a real Claude Code.** The hub tests run the real binary on both sides over a
  stand-in ssh that execs locally; `ControlMaster`, sshd's `ForceCommand` and fish parsing the
  hex word are infra's bring-up checks.
- **The drop-in mounted from a volume.** Claude Code reading `/etc/claude-code/managed-settings.d`
  when it is a read-only volume mount rather than an image directory; expected to be the same,
  and `make verify`'s `hooks` line is the check.

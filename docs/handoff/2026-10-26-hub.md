# Handoff — the hub

## First orders

**Read this, then [`../../CLAUDE.md`](../../CLAUDE.md), then [`../design.md`](../design.md) §
*The hub*.** The hub is **released as `v0.5.0`** (merged to `main` on the owner's word,
2026-10-27) and pinned by infra's hub image, but **not on the fleet**: zero still runs 0.4.7 in
the old layout until the owner's cutover (infra's `dev/README.md` § *The cutover from the old
layout*). Do not deploy, start, stop or offload anything.

## What changed

- `claude-sessions` at a terminal is the **hub's menu** over every container named in
  `CLAUDE_SESSIONS_HOSTS`, else `local` — which is the
  old single-container menu. Mockups 12 to 15 are the home (the containers), one container
  focused, a container not answering, and the home's keys. The owner left the interface to
  this repo ("interface is your call", 2026-10-26), then shaped it the same day: containers
  first; inside one, Loaded, Offloaded and a folded Archived holding everything closed; and a
  waiting session marked with an amber `!` instead of a Needs-you group. Every mockup was
  redrawn for that, from the renderer.
- `claude-sessions agent` is each container's half, over `ssh -T`; `agent exec` runs a child
  an action needs at the hub's terminal, over `ssh -t`. Everything that reads or changes a
  container's sessions still runs in the container, from the same code.
- `claude-sessions offload-all` runs every container's pass at once. The per-container
  `CLAUDE_SESSIONS_OFFLOAD=0` and the `~/.config/claude-sessions/hosts` file are gone (infra's
  design review, 2026-10-27): one switch, the hub's timer, and one list, its environment.
- `claude-sessions install DIR` writes the binary, the hooks drop-in naming `DIR/bin/…` and
  the skill — what the hub's start puts into the volume every container mounts.

## For infra

infra carries the other half (one compose file, the hub image, the base changes), with the
hub's `CLAUDE_SESSIONS_SHA256_*` filled from this release's `.sha256` assets.

## Not verified here

- **Real ssh and a real Claude Code.** The hub tests run the real binary on both sides over a
  stand-in ssh that execs locally; `ControlMaster`, sshd's `ForceCommand` and fish parsing the
  hex word are infra's bring-up checks.
- **The drop-in mounted from a volume.** Claude Code reading `/etc/claude-code/managed-settings.d`
  when it is a read-only volume mount rather than an image directory; expected to be the same,
  and `make verify`'s `hooks` line is the check.

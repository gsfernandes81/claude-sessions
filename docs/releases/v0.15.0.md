## The remote view: agents in view, the workflow browser, and the agent strip

The rest of Claude Code's tasks view, in `claude-remote`.

- **The agent strip under the footer** while agents or workflows run: `● main`, then each
  one with its latest call, time and tokens, a workflow with its `▰▱` progress bar. Down
  from an empty prompt walks into it. Enter on an agent shows it, on a workflow opens its
  browser, on `main` comes back, and `x` stops one.
- **An agent in view.** Enter in the strip, `f` in the tasks list, or Enter on a finished
  agent shows that agent's own conversation, live, between teal rules carrying its name.
  Esc interrupts it. The prompt is disabled there and says `headless claude can't message
  agents`, since headless claude refuses to message an agent.
- **The workflow browser**: phases beside the chosen phase's agents (stacked under 60
  columns), each agent's model, tokens and time. Enter on an agent opens its own pane, with
  its prompt, last call and result. `f` filters by state, and `x` stops the workflow.
- **`s save`** saves a workflow's script to `.claude/workflows/<name>.js`, or to the user
  scope with Tab, and never overwrites a file.
- **Models and counts** on rows and in an agent's details (`1m 39s · 237.5k tokens · 51
  tools · Haiku 5.5`); a line counting the task notices that came while the tasks view was
  open; `Shell details dismissed` after Esc.

Not possible with headless claude, so not offered: messaging an agent, and pausing,
restarting or skipping a workflow's agents.

The wire gains `fg`/`fgo`, `tesc`, `wf` and `wsave`/`wsaved`, which an older client or relay
ignores or refuses. The holder answers a new `_save_workflow` request on its tap socket. The
registry is unchanged. For infra: pin this release as usual; the holder change reaches a
remote slot when its holder next starts. Reinstall the phone client (`claude-remote`) to see
it.

## Agent messaging: Claude Code's own, across every container; agent mail removed

- **Every session can message every other, in any container, with Claude Code's own
  `SendMessage`.** `ListAgents` in a slot lists the other containers' slots as `repo/slot`
  beside its own container's sessions. A message wakes an idle session, or reaches a busy one
  mid-turn, as Claude Code does on one machine. Replies, delivery receipts and idle notices
  come back the same way. A message to an offloaded slot, or to a container that is down,
  waits at the hub (up to 7 days) and is delivered when the slot is next live.
- **Who sent it is the hub's to say**, as with mail. The sending slot is found from the socket,
  the container from the hub's connection to it, and `from-name` is rewritten to that
  `repo/slot` on delivery, whatever the sender claimed.
- **Agent mail is gone**: `claude-sessions mail`, the mail hook, the nudge, the HTTP server
  and the three mail skills. Pi slots are not carried (the owner's call).
- **The remote view saves a model picked in it as the default for new sessions**, as the
  terminal's `/model` does.
- **Tested against the real Claude Code**: each behaviour the relay relies on has its own
  test, run in CI at infra's pin (`CLAUDE_CODE_VERSION` in `ci.yml`).

For infra, at the pin:

- **The hub's entrypoint runs `claude-sessions router`** in place of `mail-server`. The old
  name still works, as an alias.
- **`HUB_QUEUE`** (default `$HOME/queue`) holds messages waiting for a slot, and must be on a
  persisted volume. The `mail` volume, `HUB_MAIL_LISTEN`, the other `HUB_MAIL_*` variables
  and the `mail-token` files can go. Nothing listens on 8025 any more.
- **`hooks-config` output changes**: the `mail-hook` handlers are gone, and
  `"crossSessionInbound": "accept"` is new. Please update the drop-in's row in
  decisions.md.
- **The mail skills are removed from the install volume**, so the base should stop linking
  `mail-send`, `mail-read` and `mail-reply`. The managed mail policy text goes too: Claude
  Code's own rules for peer messages replace it (the owner's call).
- **`claude-sessions peer-check [CLAUDE]`**, for `make verify` and dev-smoke, exits 0 when
  that claude speaks the peer protocol the relay does. It starts claude with no prompt, so no
  request is made.
- **No mixed versions to plan for.** The router starts every container's agent itself, over
  ssh, from the binary the hub installs into the volume, so the relay's two halves are always
  the same release.

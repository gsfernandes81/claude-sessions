## The remote view: Claude Code on the phone

**`claude-remote dev`** is a client for the owner's phone (Termux) or WSL that draws Claude Code
there, from a small stream over one ssh link that reconnects by itself (owner, 2026-11-01;
`docs/remote-view.md`, mockups R1 to R10). It is this same binary, run under the name
`claude-remote` (a link to it) or as `claude-sessions client NAME`.

- **Its home is the hub's menu**, drawn on the phone from the same snapshots. Sessions running
  in a terminal are listed dim as `term: ` and stay the terminal's. Every other row opens on
  Enter, and offloaded and archived conversations resume in remote mode with their history.
  `n` starts a new one.
- **A conversation looks like Claude Code 2.1.311's fullscreen mode.** You get permission
  prompts with Claude's own "don't ask again" rule, questions with long options that scroll,
  `/model`, `/effort`, `/auto` for the mode (no shift+tab), `/rename`, `/compact`, `/copy` and
  `/exit`. Tool calls are collapsed. Scrollback and editing happen on the phone.
- **When the link drops**, the screen stays and the footer says `Reconnecting…`. Once it's
  back, only what the phone lacks is sent.

What it adds to the fleet:

- **`claude-sessions relay`** on the hub, one per connected client, run through the door as
  `ssh -T -C dev claude-sessions relay`. `claude-sessions relay --version` answers at once,
  for infra's verify step.
- **`claude-sessions remote new|open|resume`** in a container, which the relay runs over
  ssh. A remote session is still a `claude-<n>` zmx slot. Its program is
  `claude-sessions holder`, which runs `claude -p` headless (stream-json), logs its lines in
  `<registry>/<slot>.log` and serves them on `<registry>/<slot>.sock`. Attaching to the slot
  from the old menu shows one line saying it is open in the remote view. Offloading,
  archiving and mail work on it as on any slot. A connected client keeps the slot loaded.
- **The registry** gains `"driver":"holder"` on such a slot's record, and a row on the
  agent's wire gains `"remote":true`. Both are written only when set, and a release without
  them reads such a record and row as a plain claude slot. Until every container runs this
  release, a live holder socket also marks the slot as the remote view's.

For infra: pin this release. The client's ssh config for `dev` needs nothing new (it already
has `Compression yes`). Each phone or WSL machine needs the static binary installed under
the name `claude-remote`. Still to be measured from Termux before the dead-link timings
are final: cloudflared's idle timeout.

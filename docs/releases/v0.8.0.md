## Agent mail

Messages between dev containers, carried by the hub over the ssh it already has: a sender
drops a file in `/workspace/.mail/out/<to>/`, the hub stores it in its volume with its own
`From:`/`To:`/`Date:` header, deletes the sender's copy once the stored one is fsynced, and
pushes it into the receiver's `/workspace/.mail/in/<from>/` when that container answers.
Design in `docs/design.md` § *Agent mail*; the decision is infra's `docs/decisions.md`.

**New subcommands:** `mail-loop [--once]` (the hub), `mail-agent` (a container's half, over
ssh), `mail-hook` (from the drop-in). `install` now writes a drop-in with the mail hook on
`SessionStart` and `UserPromptSubmit`; the registry hook is unchanged.

**What infra's compose sets for the hub**, one line each (the loop reads nothing else):

| variable | default | |
|---|---|---|
| `HUB_MAIL` | `$HOME/mail` | the volume; mount the `mail` volume there |
| `HUB_MAIL_MAX_BYTES` | `16384` | a larger message is refused |
| `HUB_MAIL_MAX_QUEUE` | `200` | undelivered messages a receiver may have; more are refused |
| `HUB_MAIL_RETAIN_DAYS` | `90` | older messages are pruned from the volume, delivered or not |
| `HUB_MAIL_TICK` | `15` | seconds between passes |

The containers are the hub's `CLAUDE_SESSIONS_HOSTS` as today. The entrypoint starts
`claude-sessions mail-loop` in the background, supervised as the token loop is; it logs one
line per event to stdout, never a body. It touches `$HUB_MAIL/.beat` after every tick, if
`hub-health` wants a heartbeat.

**The volume's layout:** `<mail>/<to>/<from>/<stamp>.md` is a message not yet delivered;
delivered, it is renamed into `<mail>/<to>/<from>/delivered/<stamp>.md`. The stamp is
`YYYYMMDDTHHMMSS.mmmZ` (`-2`, `-3` when a millisecond is shared). A queue is everything
pending under `<mail>/<to>/`. Refusals — unknown receiver, `hub` as receiver, over the size
cap, not UTF-8, queue full — are a message from the reserved sender `hub` into the sender's
queue, so they land in `/workspace/.mail/in/hub/`.

**The hook's line**, one per new message, oldest first, nothing when there is none:

```
new message from <from>, <date>, at <path>
```

e.g. `new message from infra, 2026-10-28T03:15:00Z, at /workspace/.mail/in/infra/20261028T031500.123Z.md`.
The cursor is `/workspace/.mail/.cursor`, the receiver's; the hub never writes it.

**For the skills:** write a message somewhere else and `mv` it into `out/<to>/`, or leave it
two seconds — the agent skips a file modified in the last two seconds, so one being written in
place is not read half-way. Any file name; the stored name is the hub's stamp. A receiver's
own `From:` line is body text under the hub's header. A message in `in/` stays until the agent
removes it; the hook does not announce it twice.

**Deferred, by the owner's decision:** the owner's view of the traffic and a nudge to an idle
session — #17.

## The remote view: prompts at once, the transcript kept, ssh's status line

Three changes in `claude-remote`, all asked for by the owner on 2026-11-01.

- **A prompt shows the moment it is sent**, in its band with the braille spinner where `❯`
  goes, until claude's own echo of it arrives. A prompt queued while claude is busy keeps
  turning at the bottom until claude takes it. One sent while the link is down goes back
  into the prompt instead.
- **A new prompt no longer pushes the transcript off the screen.** The transcript's end now
  sits on the input box, so a prompt goes under what came before. A conversation that fits
  is still drawn from the top, logo and all. Mockups R2, R3 and R4 are redrawn for it.
- **The footer is the ssh sessions' status line**: the same RAM and load figures, wording
  and yellow and red thresholds as `statusline.rs`. At 80 columns it reads
  `claude-sessions/claude-3 · RAM: 0.9G / 2.0G, Load: 0.7`. Where that doesn't fit, it reads
  as an ssh session prints it, then with the figures alone, so a phone at 40 keeps the load
  in view.

Also: the holder takes a resumed conversation's transcript from its caller instead of
reading `CLAUDE_SESSIONS_HISTORY` itself. The behaviour is unchanged. Its test no longer
fails when run from a remote-view session.

Nothing changes on the wire, the hub or the containers. For infra: pin this release. Each
phone or WSL machine needs the new static binary installed as `claude-remote`.

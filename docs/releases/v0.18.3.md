## Waking checks the host, and the remote view's /model and /effort show the session's own

- **A wake now needs room on the host, not only in the container**, and wakes run one at a
  time across the fleet. Each container's memory limit is a ceiling, not a reservation, and
  together they come to more than the host has, so several wakes at once could each pass their
  own container's check. A refusal is told to the sender, with the figures.
- **A message bounced for a moment is retried within seconds**, not left until the
  container's next snapshot, which could be a minute away.
- **`/model` and `/effort` in the remote view open on the session's own.** `/model` marks
  `Default (recommended)` for a session on the default model, where it marked the model that
  default resolves to; and the session's own model before its first turn, where it marked the
  first entry. `/effort` has an `auto` stop first, the model's own effort, where a session
  with no effort set sits; it marked `medium`. Claude reports neither the alias nor the
  effort, so the holder works them out as Claude Code does (its flags, the environment, the
  settings files), tested against the real Claude Code.
- **The model and effort are on the remote view's bottom bar**, before the 5-hour and weekly
  usage (`Opus 5.5 ● high`), when the line is wide enough for both.

For infra:

- **Finding (k), closed by this release.** Before asking any container to wake a slot, the
  router now reads:
  - **the host's available memory**: `MemAvailable` in the hub's own `/proc/meminfo`, which
    in a container describes the host. It must cover a session (`mem::SESSION_COST`, 250 MB)
    plus a margin of 512 MB (`router::HOST_MARGIN`).
  - **the pool's headroom**, as well, where `CLAUDE_SESSIONS_POOL` names the pool's cgroup
    directory. It must cover the same. Unset today, so only the host figure applies.
  - **one wake at a time across the fleet**: a wake asked for while another is in flight
    waits for that one's answer.
  - A figure that cannot be read does not refuse, as the menu's own check does not. The
    container's own check (its cgroup, as in 0.18.2) still runs after these.
- **The router retries kept messages for live slots every 5 s**, with a 30 s pause for a slot
  that just bounced one. The log shows it as `message handed on (was waiting)`.
- **No change to the drop-in, the volumes or the variables.** `hooks-config` is byte-identical
  to 0.18.2.
- **The holder's log now starts with one line of its own**, `{"type":"_cfg",…}`, the model
  and effort claude started with. Taps and the relay read it; nothing of infra's reads that
  log.

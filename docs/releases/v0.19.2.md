## The remote view's plan and question dialogs, as Claude Code draws them

- **A plan to approve shows the plan.** `ExitPlanMode`'s prompt showed only the plan's first
  line, cut to 200 characters: about two rows. It now shows the whole plan as markdown under
  Claude Code's "Ready to code?", scrolled with PgUp/PgDn or the wheel when it is taller than
  the screen.
- **Its options are Claude Code 2.1.311's** (driven in a terminal, 2026-11-08): **Yes, and use
  auto mode**, **Yes, manually approve edits**, and **Tell Claude what to change**, which
  takes typing and sends it back so Claude plans again. Esc says no and stops the turn, as
  before. The mode line follows the switch as soon as the plan is approved, where it used to
  keep saying "plan mode on" until the next turn.
- **Several questions at once get Claude Code's tab row**: answered in any order with Left
  and Right or Tab and Shift-Tab, each keeping its answer, and sent from a Submit tab that
  reviews them and leaves out any unanswered (mockups R4d and R4e). The view used to ask them
  strictly in turn.

## The remote view keeps what you typed

- **An unsent prompt survives leaving the conversation.** Leaving by Ctrl+\, `/home` or the
  session ending, quitting the client, or pausing typing for a second saves it on the phone
  (or WSL), in `~/.local/state/claude-remote/drafts.json`. It comes back when that
  conversation is opened again, whether it ran on, was offloaded and resumed, or archived.
  Its pastes are kept too. It is keyed by container and conversation id, so a reused slot
  name never shows someone else's draft. Sending or clearing the prompt drops it.
- **Pasting the same text again expands its stand-in**, as Claude Code 2.1.311 does: after a
  long paste becomes `[Pasted text #N +L lines]`, the footer says `paste again to expand` for
  eight seconds, and the same paste again puts the full text in its place to edit.

## The menu takes vi's j and k

- **`j` and `k` move the cursor down and up**, as the arrows do, at the door's home, in a
  container's list and on the remote view's two homes. They are unlisted, like the arrows, so
  no screen changes.

For infra:

- **No change to the drop-in, the volumes or the variables.** `install` and the hook path are
  untouched since 0.19.1, so `hooks-config` is byte-identical to 0.19.1.
- **No change to the hub's wire** (`src/proto.rs`) or to the load line's shape.
- **The phone's protocol with the relay** gains one optional field: a `perm` answer of
  `a:"y"` may carry `m` (a permission mode), which a 0.19.2 relay sends to claude as a
  `setMode` alongside the allow. A relay from before 0.19.2 ignores `m` and allows plainly,
  which leaves plan mode for manual rather than auto: a working fallback, not a failure.
- **What the relay reads from claude**: a `system/status` line with `status: null` and a
  `permissionMode` now updates the session's mode. A line without it reads as before.
- **The relay also reads the conversation id from claude's SessionStart hook lines**
  (`system/hook_started` and `hook_response`), so the meta op's existing `sid` is filled as
  soon as claude starts rather than at its first turn. No new field. A phone on 0.19.2 behind
  a 0.19.1 relay still keeps drafts, but one for a resumed, not yet prompted conversation
  comes back only after its next prompt. The drafts file lives only on the phone; nothing
  new is stored on the hub or in a container.

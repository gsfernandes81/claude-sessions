## The door's RAM and swap are what the machine has

- **The hub's load line, at the door and in the remote view's footer, says the machines'
  own memory and swap** where no pool is mounted: the host's used (`MemTotal` less
  `MemAvailable`) and total memory, and `SwapTotal` less `SwapFree` against `SwapTotal`,
  each machine counted once by its `boot_id`, as the load already was. Until now it added up
  every answering container's cgroup ceilings, which on the Pi read `RAM: 4.0G / 16.0G,
  Swap: 4.0G / 32.0G` for a machine with 4 GB and 10.8 GB (owner, 2026-11-08).
- **How.** The hub reads its own `/proc/meminfo`, which describes the host, and each agent
  sends its machine's memory and swap in its header beside the load, core count and
  `boot_id` it already sent. The pool, where the hub can read one, still comes first.
- **Agents too old to say what their machine has** are still added up as before, for a
  machine no reading describes. On a fleet of one host the hub's own reading covers it, so the
  door reads right as soon as the hub is on 0.19.1, before any container restarts.

For infra:

- **No change to the line's shape.** The fields, their order and their punctuation are as
  in 0.18.5 (`RAM`, `Swap`, `Load`, the host), so the smoke test's pattern still matches; only
  the door's figures change. A session's own status line is unchanged: it never read the
  containers' sum.
- **The wire.** A header's `load` object carries `memory` and `swap`, each `[used, total]`
  in bytes, beside `centi`, `cores` and `boot`. A hub or agent older than 0.19.1 ignores or
  omits them; a reading without them counts as unknown, never zero.
- **No change to the drop-in, the volumes or the variables.** `hooks-config` is byte-identical
  to 0.19.0.

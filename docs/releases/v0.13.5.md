## The remote view: selecting, /copy, and send-now as Claude Code does them

Fixes to `claude-remote` and the hub's relay, from the owner's use of 0.13.4 (2026-11-02). Each
was checked against Claude Code 2.1.311 driven in a pty.

- **Drag to select.** A drag over the conversation selects it in Claude Code's selection
  colour, and letting go copies it. The phone holds the mouse for the wheel, as Claude Code's
  fullscreen mode does, so the terminal's own selection could not work. The phone says how it
  copied in Claude Code's words: `copied N chars to clipboard` under Termux, or `sent N chars
  via OSC 52 · …` elsewhere.
- **`/copy` is `/copy` again.** The suggestion list swapped it for `/design:ux-copy`, the only
  command with `copy` in it that headless claude lists. A command typed whole now runs as
  itself, and the phone's own commands are in the list.
- **Ctrl+X Ctrl+S no longer interrupts a tool call.** As in Claude Code's terminal, a running
  Bash command or subagent goes to the background and the same turn takes the waiting prompt
  in. With no call running, it still drops the turn quietly. Headless claude's own `send_now`
  had stopped the turn and rejected its call.

The wire is unchanged. The relay changed: `now` now sends claude `background_tasks` while a
call runs. For infra: pin this release. The hub must be rebuilt, and the client installed again
on the phone and WSL.

## The remote view runs `!` commands, as Claude Code does

- **`!` first in the prompt is shell mode**, as in Claude Code 2.1.311: `!` in place of `❯`,
  the prompt's rules and `! for shell mode` in Claude Code's pink, no slash-command list. A
  `!` typed, pasted or recalled from history enters it; Backspace on an empty prompt leaves
  it. Enter runs the command; Esc stops it.
- **It is drawn as Claude Code draws it**: `! command` on its band, `⎿  Running…` until it
  ends, then its output with errors in red, three lines and `… +N lines (ctrl+o to expand)`
  until Ctrl+O, or `(No output)`.
- **A `cd` carries to the next command, and `cd -` goes back.** The holder runs each command
  in the user's bash (zsh if that is the shell; a fish login shell is passed over, as Claude
  Code passes it over) from the directory the last one ended in, under the Bash tool's
  two-minute timeout (`BASH_DEFAULT_TIMEOUT_MS`) and 30,000-character output cap. A job left
  running with `&` is not killed and holds nothing up.
- **Claude reads it and answers**, as Claude Code's does by default: the command and its
  output join the conversation and start a turn, unless `respondToBashCommands` is `false` in
  the settings or the command was interrupted, when they are added behind Claude Code's
  caveat and wait for the next prompt. They are in the transcript, so a resume draws them.
- **One difference from Claude Code:** there, `!` and Claude's Bash tool share a shell; a
  headless claude's Bash keeps its own directory. When a command leaves the shell somewhere
  new, Claude is told so, out of the view.

## The remote view's dialog text fields edit like the prompt

- A dialog's text field — a question's "Type something.", a plan's "Tell Claude what to
  change" — takes the prompt's editing keys: Left and Right, a word at a time with Ctrl or
  Alt, Home, End, Delete, Ctrl-A, Ctrl-E and Ctrl-U, with the cursor drawn where it is. It
  used to type and take Backspace at the end only.

For infra:

- **No change to the drop-in, the volumes or the variables.** `install` and the hook path are
  untouched since 0.19.2, so `hooks-config` is byte-identical to 0.19.2.
- **No change to the hub's wire** (`src/proto.rs`) or to the load line's shape.
- **The phone's protocol with the relay** gains one op, `bash {x, u}`, which the relay sends
  to the slot's holder as a `{"type":"bash_command"}` line. A relay from before 0.19.3
  answers it with an error (`"bash" is not something the relay knows`), so a 0.19.3 phone
  behind an older hub says so rather than running anything. Install the client with the hub,
  as before. The reducer's new items, `bash` and `bout`, are skipped by an older phone.
- **The holder now runs commands itself**, as the slot's own user, in the slot's working
  tree: the same trust as Claude Code's `!`, which runs without permission prompts. It
  writes three short-lived files beside the slot's log in the registry
  (`<slot>.bang.out`, `.err`, `.cwd`) and removes them after each command. A holder from
  before 0.19.3 (a container not yet restarted onto the new hub) passes the line to claude,
  which runs it in its session directory without adding it to the conversation.
- **What the holder sends claude** gains `user` lines with `shouldQuery` set, which 2.1.311
  accepts (measured, and held by `tests/claude_bang.rs` against the real claude).
